# ARCHIPELAGO — browser flight simulator

Three.js flight sim, plain ES modules via import map (no bundler, no build step).
v2: 5 aircraft, free flight, ring race, and a 7-lesson flight school. Maps: procedural archipelago,
stylized Singapore, alpine, plus real-world airfields (streamed elevation). v7: faceted low-poly terrain, scattering-style sky + stars,
low-poly cumulus, instanced forests, clear-water shallows, cockpit frames, fly-by camera,
wingtip vortices / airshow smoke, live 3D menu backdrop, dynamic resolution.
v8: spring chase cam + shake, control expo / Shift fine control, noise-based prop audio with Doppler,
post FX (bloom/grade/flare), ocean swell + coastal foam + spray, nav lights/strobes + retracting gear,
archipelago villages/lighthouses, and visual-only traffic (boats, circuit planes, birds).
v9 (AAA pass): lofted airframes (modelkit.js), ICAO runway markings + procedural asphalt on every map,
airfield lighting with approach lights and a live PAPI, RAIN/STORM weather (overcast deck, rain,
lightning, wet runway braking), and instant replay with cinematic cameras.
v10: the art direction moved from faceted low-poly to a realistic look — smooth seamless terrain with a
procedural ground shader, PBR aircraft reflecting a sky environment map, soft billboard cumulus, smooth ocean.
v11: 3D cockpit interiors with live canvas instruments, path-independent colour pipeline (display.js) with a
scene-referred bloom threshold, Singapore facades + beach coastline, horizon-first terrain streaming.
v12: planar water reflections, and engine sound synthesised from the engine's physical state in an AudioWorklet
(cylinder firing through an exhaust waveguide + prop blade-pass; turbofan fan tone, buzzsaw, core whine, jet roar,
afterburner), with cockpit/exterior voicing and fore/aft directivity.
Real-world airfields add OpenStreetMap scenery (buildings at tagged heights, airport pavement and other runways, roads,
lakes, land cover driving ground colour and forests) from one Overpass query per load.

## Run / test

- `npm run serve` → python http.server on :8123, open http://localhost:8123
- `npm test` → headless physics suite (Node, no browser, ~1 min; must stay green)
- `npm run e2e` → puppeteer E2E against :8123 (server must be running; writes test/shots/*.png)
- `node test/bootcheck.mjs` → fast boot/menu/aircraft-swap smoke check
- `docs/AAA-CHECKLIST.md` → the agreed meaning of "AAA" for this project: every feature area rated against MSFS / X-Plane, with evidence. Update a row when you change that area.
- `node test/osmstress.mjs [n]` → times the OSM pipeline on a SYNTHETIC dense city (40k buildings: ~1.4 s main thread, 481k triangles, 64 draw calls)
- `npm run sounds` → renders engine scenarios (start-up, run-up, fly-bys, afterburner) to test/shots/engine-*.wav

## Architecture (who owns what)

- `src/physics/` — pure JS flight dynamics, **no Three.js imports ever** (headless tests depend on this). flightModel.js = forces/moments/integration; groundContact.js = gear/probes from `ac.p.gear`/`ac.p.probes`.
- `src/physics/envelope.js` — Vne/Vfe/Mach/g limits, the damage accumulator and `vSpeeds()`. THREE-free; `modes.js`, `panel.js` and the tests all read V-speeds from here so the menu card, the ASI arcs and the airframe limits cannot disagree.
- `src/physics/wind.js` — THREE-free wind field (steady/gusts/turbulence); aero uses air-relative velocity, gear stays inertial; trim rides on `controls.trim`; trainer can set `ac.engineFailed`.
- `src/aircraft/params.js` — per-aircraft physics presets, also THREE-free. catalog.js joins params + mesh builder + HUD/camera meta. meshes.js = the 5 airframe builders.
- `src/aircraft/modelkit.js` — the airframe kit: `loft()` (fuselage sections through a profile), `surface()`/`wingHalf()` (NACA-section wings, tails, fins; control surfaces split off at `hingeC` and hinged on their real hinge line), all non-indexed with ONE colour per face painted by a callback at the face centroid (that is the livery: stripes/windows land on face rows). Profiles are Catmull-Rom refined (`refine`, the paint still sees the ORIGINAL row index) and `smoothNormals()` averages normals across faces except creases sharper than ~48° — so the skin is smooth while paint edges stay crisp. Materials are PBR (MeshPhysical paint with clear coat, glossy glass) and DoubleSide so loft winding never matters. Gear is placed from `params.gear` contact points (`wheelY`) — keep it that way, or the airframe floats/sinks.
- `src/maps/` — map modules implementing the FlightMap contract (typedef in archipelago.js). Render height (`map.height`) is separate from collision height (`max(height, obstacleTop)`); ground effect/AGL use terrain only.
- `src/terrain.js` — generic chunk streamer, plus instanced trees on a ±1.5 km ring of fine chunks (optional `map.forest(x,z,h,slope)` → 0..1 and `map.conifer(h)`; a map without `forest` grows none; LOW quality turns them off). `src/maps/noise.js` is shared noise for COSMETIC layers only (forest, meadow) — never feed it into `map.height`, the state hashes depend on heights.
- **Art direction: realistic (v10; it was faceted low-poly through v9).** terrain.js builds every chunk as an indexed smooth grid; heights are sampled one cell past the chunk edge so normals (central differences) and slopes match the neighbouring chunk exactly — no lighting seams. Map `color()` is called per VERTEX. `terrainMaterial()` (Lambert, one light evaluation) injects world-space detail: macro tone per vertex (~250 m), mid tone and fine grain per pixel, dry patches on vegetation, triplanar crags on steep faces, a bump normal near the camera, all faded with distance so nothing shimmers. It is the costliest full-screen shader, so measure (`test/shots.mjs` prints an fps probe) before adding to it. The coarse tier is sunk ~250 m wherever the fine tier covers it (vertex shader), or its 200 m interpolation pokes through valleys. All maps paint from `src/maps/palette.js` (`PAL`, `seabed()`, `beach()`, `facetJitter()`, `decalMaterial()` — runway slabs need its polygon offset or they z-fight with the flat apron at range).
- `src/environment.js` — sky dome shader + a PMREM environment map of it (applied per material with `env.applyEnv`, NOT `scene.environment`, which would also hit the Lambert world; rebuilt only when the palette changes, never per frame), soft billboard cumulus (one instanced draw call, a procedural puff texture, cluster centres in a uniform array so `setCover` and wrapping stay cheap), ocean with analytic swell normals + fine ripples, semi-transparent ocean (the turquoise seabed shows through as shallows near the aircraft; opaque beyond ~2 km), time-of-day palettes. Planar water reflection (`env.renderReflection(camera)` before the main render): a mirrored camera with an oblique near plane at sea level renders into a 1/3-res HalfFloat target, compiled into the ocean only via the `OCEAN_REFL` define and only on the full-detail path (`setDetail(1)` + HIGH quality). The target holds scene-linear colour, so the ocean shader converts it with `dmToScreen()` (display.js) before mixing. **Never toggle `renderer.shadowMap.autoUpdate` (or other renderer state) around an extra pass**: doing it in the reflection pass raised GL_INVALID_OPERATION (shadow sampler/texture mismatch) and silently dropped every opaque draw; e2e now fails on any GL_INVALID console line. `src/trails.js` — ribbon trails (wingtip vortices on G/alpha, `K` smoke); pooled, no per-frame allocation.
- `src/camera.js`: chase cam is a critically damped spring on the offset from the aircraft (no steady-state lag). `C` cycles CHASE/COCKPIT/ORBIT (tests rely on exactly that cycle), `V` toggles FLYBY, wheel zoom, left-drag free-look, per-aircraft cockpit frame (`catalog camera.cockpit.frame`: cabin/canopy/airliner), `updateMenu()` = the slow showcase orbit behind the menu. The menu backdrop is fed by `world.preview(sel)` (aircraft + time of day only; maps still load on START).
- `src/post.js`: EffectComposer (half-res bloom, grade/vignette/flare, OutputPass). HIGH quality + POST FX setting only, and it switches itself off for the session when dynamic res is pinned at 0.6 with fps < 30, so headless e2e ends up on the plain `renderer.render` path within seconds. Nav lights and lights meant to bloom use `toneMapped: false`.
- `src/traffic.js`: visual-only boats, pattern traffic and bird flocks; pooled, never collides, off on LOW. Archipelago villages/piers/lighthouses live in `createScenery` and never touch `map.height`.
- `src/maps/runwayPaint.js` — `runwayDressing()` builds every map's runway in runway-local metres: asphalt slab shaded in its fragment shader (lanes, patches, grain, rubber, wet sheen via the shared `RUNWAY_WX` uniforms) plus ICAO markings as real quads and designator text planes. `src/runwayLights.js` — point-sprite lights from `map.runway` (x0..x1 along heading from the origin, so real-world maps report x0 = -halfLen): edge/centreline/threshold, approach lights + sequenced flashers off the x0 end, and a PAPI at spawn+300 m (the same aim point as training.js) whose units switch red/white from the camera's angle.
- `src/maps/airfieldKit.js` — apron/taxiway with taxi markings, arched hangar, control tower, fuel truck (archipelago field). Visual only, no obstacles; parked aircraft reuse `clubPlaneGeometry()` from traffic.js (one merged draw call).
- `src/weather.js` — the SKY half of the RAIN/STORM presets (the wind half is `WEATHER` in wind.js; `WET_WEATHER` drives `physEnv.wet`, which only scales brake friction). Overcast deck that follows the camera, rain streaks (one LineSegments, all motion in the vertex shader), cockpit windscreen beads, lightning + thunder. It drives `env.setSky({ overcast, vis, inCloud, flash })`; environment.js re-greys the whole palette from the time-of-day table, so never write palette uniforms anywhere else.
- `src/maps/osm.js` (THREE-free: Overpass query, parse, ring joining, 16 m land-cover raster, building obstacle grid) + `src/maps/osmMeshes.js` (merged per-1 km-tile building meshes with the sgLandmarks facade shader, pavement, other runways via `runwayDressing`, roads, lakes) feed `realworld.js`. **Commit rule:** land cover may change `height()` (pavement flattened to field elevation), `color()` and `forest()` only if the data arrived before the terrain was built: main.js waits up to 15 s, then calls `map.commitScenery()`. Data that lands later adds buildings and roads only, so render and collision never disagree. Offline or blocked degrades to the old scenery. The GET is cached with the Cache API (`archipelago-osm-v1`). Attribution (`map.attribution`, `#map-credit`) must stay visible whenever OSM data is used (ODbL). Tests use a HAND-WRITTEN fixture in Overpass format (`test/fixtures/make-osm-fixture.mjs`), never presented as real data; this container cannot reach Overpass.
- `src/engineSynth.js` — the engine sound, THREE-free and WebAudio-free so Node tests render it. `src/engineWorklet.js` hosts it as an AudioWorklet driven by k-rate AudioParams (no per-frame messages); `ENGINE_SOUNDS` holds each aircraft's voice (cylinders, blades, pipe length, fan blades, N1 rpm). The synth glides its own parameters per block, so audio.js just sets values. Frequencies are physics, and test/physics.test.js checks them in the spectrum: firing = rpm × cylinders / 120, blade-pass = rpm × blades / 60, fan tone = N1 × fan blades. Keep it allocation-free per sample and under ~8% of a core per voice. audio.js keeps the old oscillator engine only as the no-AudioWorklet fallback (`audio.engineVoice` says which one runs).
- `src/replay.js` — instant replay. `createRecorder()` is THREE-free (Float32Array ring, 30 Hz of sim time, 150 s). Playback fills a ghost shaped like `ac`; main.js renders from `view = replaying ? ghost : ac` and NEVER writes the physics state. Game state `replay` (modes.js) returns to whatever it was opened from. Replay keys are taken in the capture phase so flight controls never see them; `C`/`X`/`Esc` route through modes.js.
- `src/cockpit.js` + `src/instruments.js` — 3D cockpit interiors (v11) in the aircraft BODY frame around the eye point (`catalog camera.cockpit`; `glass: true` gives a canopy aircraft glass displays). Instruments are a CanvasTexture redrawn at 15 Hz (also the emissive map: backlit at night). In COCKPIT view main.js hides meshes tagged `userData.hull` (meshes.js `H()`), so wings/props/engines stay visible through the glass — tag any new fuselage/canopy mesh or it will block the view. The DOM six-pack (`I`) no longer auto-shows; it still carries the cold-and-dark switches.
- `src/rings.js` — parameterized gates (race + training themes); `src/modes.js` — menu/state machine; `src/main.js` — swap lifecycle + frame loop.
- Body frame: +x forward, +y up, +z right. Body rate r about +y: **positive = nose LEFT** (sign mistakes here are the #1 physics bug source).

## Hard-won gotchas (do not re-learn these)

- **Headless Chrome starves rAF** unpredictably; the main loop has a 250 ms setTimeout watchdog with a generation ticket (see main.js `schedule()`). Never drive boot/pre-gen loops with rAF.
- **Never use page.click/page.keyboard in tests** — headless input dispatch waits on compositor frames and hangs when the compositor stalls. Dispatch DOM events via `page.evaluate` (see test/e2e.mjs helpers).
- `npm run school` and `npm run checks` are fully green since v11. They had failed since before v8 for three reasons, all fixed. ATC "Changi 02L" read the transcript before the map swap finished, so it saw the previous field. Lesson 3: the autopilot ran once per rendered frame and restarted its blend from the keyboard-recentred axis every frame, so at a few fps it went into bang-bang control. It now runs inside the 120 Hz loop from its own command memory, with ALT-hold auto-trim integrators. Lesson 7: the scripted pilot wrote controls from a setInterval that `poll()` recentred away, so nobody was flying the crosswind rollout. **Anything that drives controls from outside (tests, tools) must write right after `poll()`, not on a timer.** `test/aptune.mjs` is the headless autopilot harness.
- **In e2e, always `press(k)` (keydown+keyup), never a bare `keyEv('keydown', …)`** — controls.js tracks held keys, so a keydown without its keyup leaves that axis stuck for the REST of the suite. A stray held ArrowDown in a menu test cancelled the ArrowUp during rotation and rolled the aircraft off the runway, failing "airborne and climbing", "HUD live" and the minimap check ~40 lines later. `hold()`/`release()` exist for deliberately-held keys.
- **Wait on SIM time in browser tests, not wall time.** Headless frame rate swings 3 to 7 fps with what is on screen, so a `wait(4000)` is anything from 1 to 4 s of flight. `simSettle(ms, until)` in test/e2e.mjs waits on `__sim.simTime` with an optional early-exit predicate; use it for anything the sim has to fly through (taxi holds, race legs). Key holds ramp the throttle between polls, so set `controls.state.throttle` explicitly after a `W` hold when the exact value matters.
- Lesson step references (altitude, heading) must not latch the moment the previous step completes: the student is still mid-manoeuvre. The lesson 3 level step re-anchors whenever the aircraft leaves its ±100 ft band; it used to latch at exactly 1,500 ft AGL and was unpassable for anyone who levelled off higher.
- Puppeteer resolves a pinned Chrome build that may not be installed. If a browser test dies with "Could not find Chrome (ver. …)", run it with `PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` rather than downloading one.
- Puppeteer launches need `--enable-unsafe-swiftshader` and generous `protocolTimeout`; screenshots may fail when the compositor is stalled (wrap in try/catch).
- Physics runs at fixed 120 Hz with dt clamp 0.25 s; sim-time ≈ wall-time only if the frame loop ticks ≥4 fps.
- **The scene is fill-rate bound** (sky, ocean, clouds, terrain all cover the screen). Under SwiftShader that is what decides whether timing-sensitive e2e checks (cold-start crank, lesson-1 taxi) pass. Dynamic resolution (main.js `adaptResolution`, setting `autoRes`) drops render scale to 0.6 when fps sags, which put headless runs at ~6 fps vs ~3.7 before v7. Measure with a perf probe before adding anything screen-covering; tree shadow casting alone cost ~0.3 fps and was removed.
- **Colour pipeline (v11):** every hand-written `ShaderMaterial` is wrapped in `displayMatch()` (src/display.js). Its `gl_FragColor` is the colour you want ON SCREEN; displayMatch appends the exact inverse of three's ACES + sRGB and the standard chunks, so it displays identically with POST FX (OutputPass tone maps) and without (in-shader tone mapping). Before v11 these shaders skipped tone mapping in the plain path only, so the same sky was deep blue without post FX and washed out with it. Custom shaders that fade to fog must use `env.screenFog` (= `displayOf(scene.fog.color)`), the fog as built-ins display it. Bloom (post.js) thresholds in SCENE-linear units at 6 (scene 8 ≈ display white): only the sun, glitter and HDR lights bloom — light sources must be driven above it (display.js headroom, nav cores ×12). New custom shader → wrap it, or it will look different per path.
- Elevator authority: `Cmde` ≈ 0.35–0.55 in these normalized units; higher over-rotates and tail-strikes. **This binds the propwash factor too** — `qWash` scales `Cmde`, so its cap must keep the product under ~0.55 or every takeoff ends in a strike just after rotation.
- **v6 flight model — the two firewall invariants.** Post-stall drag and the two-station strip roll damping are both written so they are *provably* inert below the stall (`sep === 0`, and the strip pair collapses algebraically to `Clp*(pb/2V)`). That is what lets the stall/roll/envelope work coexist with the byte-identical cruise state hash. `test/physics.test.js` section 18c asserts both directly — if you change `liftCoeff`, keep them true.
- **A hands-off single no longer flies straight.** Slipstream swirl gives a real left-turning tendency, and the C172 is slightly spirally divergent, so any test that flies fixed controls for more than ~20 s needs a wings-leveler and coordinated rudder or it will spiral. Several existing tests had to gain one. Engine torque roll is deliberately *not* modelled — there is no aileron trim to hold against it.
- Turbulence rolls the aircraft through a spanwise gust gradient sampled at the wingtips. It must stay **slow** (~200 m eddies): an early version varied at ~29 Hz as the aircraft flew through it and the roll mode, time constant under 0.1 s, filtered it out entirely.
- E2E "flies" by teleporting: always set orientation (yaw quaternion) to match velocity, else sideslip aerodynamics veer the plane off course; approach gates from ≤150 m or lift trim balloons the plane above the ring.

## Conventions

- Art review: `test/showroom.mjs`, `test/shots.mjs`, `test/wxshots.mjs`, `test/replayshots.mjs` write screenshots (they pin settings: no tour, no ATC, autoRes off). Use them before and after any visual change.
- Verify with the scripts above, not by eyeballing — extend test/physics.test.js for physics changes, test/e2e.mjs for flow changes.
- localStorage keys: `archipelago.best.{map}.{aircraft}` (+ `.splits`), `archipelago.training`, `archipelago.sel`, `archipelago.settings`, `archipelago.logbook`, `archipelago.plan.{map}`.
- Menu/pause/crash/results screens are translucent over the live scene — keep new overlay screens legible with a left-weighted scrim rather than an opaque background.
- Aesthetic: PFD/avionics HUD (B612 font, amber cautions, red warnings, magenta race guidance); realistic world (PBR aircraft, smooth terrain). Keep new UI in that system.
